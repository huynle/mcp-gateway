# Machines (`internal/machines`, `mcp-gateway login` / `up`)

An **enrolled machine** connects several local MCP servers to the gateway from a vetted computer, repeatably and headless, without a long-lived secret on disk. It replaces the hand-made `mgt_` tunnel token for that use; legacy tunnels keep working unchanged ([tunnel.md](tunnel.md)). Design: Brain decision `ldjix4y1` (needs-review); the client side is `internal/machineclient` and the `mcp-gateway login|status|up|logout|service` subcommands.

```
mcp-gateway login ──device flow / enrollment code──▶ gateway: machine (Ed25519 public key, owner)
mcp-gateway up    ──signed assertion──▶ /machine/token ──▶ mgm_ token (10 min)
                  ──PUT /machine/v1/servers/{name}──▶ tunnel linked to the machine + private MCP server
                  ══ one WebSocket /machine/v1/connect ══ carries every tunnel of the machine
```

## For users

1. Install the CLI (see [tunnel.md](tunnel.md#install-the-client)).
2. `mcp-gateway login --gateway https://gateway.example.com`. It prints a code like `BCDF-GHJK`, the key fingerprint (four groups of four characters, e.g. `kPrK _qmx VWaY VA9w`) and a link to `/activate`. Open the link **signed in**, check that the machine name, the fingerprint and the requesting IP match, and press **Approve**. The machine becomes **yours**: the account that approves it owns it, whoever started `login`. Never approve a code someone sent you.
3. List your servers in `~/.config/mcp-gateway/config.yaml` and run `mcp-gateway up` (or `mcp-gateway service install`). Every server becomes a private MCP server of yours with its tools disabled; `up` prints the review links. Approve the tools in the browser as for any server.
4. **Machines** (`/machines`) lists your machines: name, fingerprint, status (connected / offline / revoked), created, last seen, last IP and servers. **Revoke** cuts the machine off at once (its connection closes, its servers go offline; the servers and their reviews stay). `mcp-gateway logout` revokes the machine from the machine itself.

Headless hosts: on **Machines → Enrollment codes** create a one-time code (`mge_…`, valid 1 hour, 24 hours or 7 days, shown once; at most 10 unused codes) and run `mcp-gateway login --enroll-code mge_…` on the host. The machine is the code creator's. Revoke unused codes you no longer need.

Admins see every machine on **All machines** (`/admin/machines`) and can revoke any.

Running `login` again with the same machine name **replaces** the old machine: the old one is revoked (reason `replaced`) and its tunnels and servers move to the new key (needs-review: chosen so that re-enrolling after a lost key keeps the servers and their reviews).

## Security model

| Property | How |
|---|---|
| Private key never leaves the machine | Ed25519 key generated by the CLI; the gateway stores only the public key (`machines.public_key`) and its RFC 7638 thumbprint (the fingerprint) |
| No long-lived bearer secret | The machine signs a JWT assertion per token request; access tokens live 10 minutes |
| Assertion | header `{"alg":"EdDSA","typ":"JWT"}` only (no other algorithm, no embedded key); `iss` = `sub` = machine id; `aud` = `<GATEWAY_BASE_URL>/machine/token`; `iat`, `exp` with `exp - iat ≤ 5 min`; ±60 s clock skew; `jti` (16–128 printable characters) recorded until expiry: a replay is refused |
| Access token | `mgm_<8>_<43>` (gateway token shape), SHA-256 at rest (`machine_access_tokens`), bound to the machine. **Every use** re-reads the machine and its owner: revoked machine or owner not active → 403 `revoked` |
| Least privilege | Accepted only by `/machine/v1/*`. `/mcp`, the portal, `/tunnel/connect` and the OAuth endpoints refuse it. A machine manages only servers backed by its own tunnels; a name already used by any other server → 409 `name_taken`. A machine connection serves only tunnels linked to that machine |
| Device flow | Device code `mgd_…` (256 bits) and user code (8 letters from `BCDFGHJKLMNPQRSTVWXZ`, ≈ 2^34.6) stored as SHA-256 only; 10-minute expiry; the machine id is handed out once |
| Approval page | `/activate` only for signed-in **active** users (pending users are sent to `/pending`, disabled users have no session), CSRF on POST, the approved request id must match the code typed; wrong codes are limited to 10 per minute per user. The page shows name, fingerprint (4x4 and full), requesting IP, client version and time |
| Rate limits (per client address, per minute) | device authorization 10, enroll 10, failed token requests 30 → 429 with `Retry-After` |
| Enrollment codes | `mge_…`, SHA-256 only, consumed in one `UPDATE … RETURNING` (concurrent use: exactly one wins), refused if the owner is not active; every failure is 400 `invalid_code` |
| Revocation | revokes the machine's tunnels in the same transaction; closes the live connection on this replica at once (close code **4003**) and on other replicas within `MachineSyncInterval` (5 s) |
| Audit (never keys, codes, tokens or assertions) | `machine.device_requested` (system), `machine.approved`, `machine.denied`, `machine.enrolled`, `machine.revoked` (with `reason`), `machine.enrollment_code_created`, `machine.enrollment_code_revoked`. Connections and disconnections are logged only (`tunnel: machine connected` / `disconnected`) |
| Caps | `machines` per user (`GATEWAY_CAP_MACHINES`, default 5; [settings.md](settings.md)); a machine's servers and tunnels count against `servers` and `tunnels` (409 `cap_exceeded`). Registering servers needs the add-server permission (403 `not_permitted`) |
| Account deletion | deletes the user's machines (tokens and assertion ids cascade), enrollment codes and decided requests; the data export includes machines and codes (no keys or hashes) |

## Endpoints

Errors are JSON `{"error":"<code>","error_description":"…"}`; every answer is `Cache-Control: no-store`.

| Endpoint | Auth | Request → answer |
|---|---|---|
| `POST /machine/device_authorization` | none, rate limited | `{"name","public_key":JWK,"client_version"}` → `{"device_code","user_code","verification_uri","verification_uri_complete","expires_in":600,"interval":5}`. Name `[a-z0-9][a-z0-9_-]{0,62}`, key `{"kty":"OKP","crv":"Ed25519","x":…}` without `d`; unknown fields are refused (400 `invalid_request`) |
| `GET/POST /activate` | portal session | enter or confirm a user code; Approve / Deny |
| `POST /machine/token` (form) | none | `grant_type=urn:ietf:params:oauth:grant-type:device_code&device_code=…` → 400 `authorization_pending` / `slow_down` (interval +5 s, at most 60) / `access_denied` / `expired_token` (also unknown or already redeemed), or 200 `{"machine_id","name","gateway"}` once. `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=…` → 200 `{"access_token":"mgm_…","token_type":"Bearer","expires_in":600,"scope":"machine"}` or 400 `invalid_grant` for any failure. Other grants: 400 `unsupported_grant_type` |
| `POST /machine/enroll` | none, rate limited | `{"code":"mge_…","name","public_key","client_version"}` → 200 `{"machine_id","name","gateway"}`, 400 `invalid_code`, 409 `cap_exceeded` |
| `GET /machine/v1/self` | `Bearer mgm_` | `{"machine_id","name","owner","servers":[{"name","server_id","tunnel_id","status":"online"|"offline","approved_tools","pending_review","review_url"}]}` |
| `PUT /machine/v1/servers/{name}` | `Bearer mgm_` | `{"kind":"http"|"stdio","path":""}` → 200 `{"name","server_id","tunnel_id","created","review_url"}`. Ensures a tunnel linked to (machine, name) and the owner's private server `{name}` at `tunnel://<tunnel id><path>` with auth none; idempotent (a changed path updates the URL). 400 `invalid_name` / `invalid_request`, 409 `name_taken` / `cap_exceeded` / `locked` (published), 403 `not_permitted` |
| `POST /machine/v1/servers/{name}/refresh` | `Bearer mgm_` | rediscovers through the live connection as the owner (like the portal's Refresh; **never approves**) → 200 `{"version","added","changed","removed","review_url"}`; 409 `offline`; 404 `not_found` (no such server on this machine); 502 `refresh_failed` |
| `POST /machine/v1/logout` | `Bearer mgm_` | revokes this machine (reason `self`) → 204 |
| `GET /machine/v1/connect` | `Bearer mgm_` | WebSocket, subprotocol `mcp-gateway-machine.v1` ([tunnel.md](tunnel.md#machine-connections)) |

Missing, malformed, unknown or expired machine token: 401 `invalid_token` (`WWW-Authenticate: Bearer realm="mcp-gateway-machine"`). Revoked machine or inactive owner: 403 `revoked`.

## Schema (migration 00030)

`machines` (owner's rows, RLS; a live name is unique per owner), `machine_device_requests`, `machine_access_tokens`, `machine_assertion_jtis` (jobs role only), `machine_enrollment_codes` (owner's rows, RLS). `mcp_tunnels` gains `machine_id` + `server_name` (composite FK to `machines (id, owner_user_id)`, so a tunnel always has its machine's owner; a check makes a row either a legacy tunnel with a `token_hash` or a machine tunnel without one; one live tunnel per machine server). `gateway_resource_caps` / `gateway_user_resource_caps` gain `machines`. The token endpoint, enrollment and the machine API run through `WithJobs` with explicit owner checks (no user is known yet); the portal lists a user's machines and codes as that user.

## Wiring

`cmd/gateway/machines.go`: `newMachines` builds `machines.Service` over the federation (`machines.NewStore` with the caps limiter, `machines.NewServers` over the connector Manager, snapshots and the servers portal's client factory, and the tunnel service); `withMachineRoutes` mounts the public endpoints on the top-level mux, outside the portal like `/tunnel/connect` (the WebSocket needs the raw connection; the reverse proxy must allow WebSocket upgrades on `/machine/v1/connect`); `withMachinePages` mounts the pages through the portal. Without a key provider there is no federation and no machines.

The client side of the connection is `tunnel.NewMachineAgent(tunnel.MachineAgentOptions{GatewayURL, Token, Targets})`: `Token` returns a current `mgm_` token before each connection attempt, `Targets` maps tunnel id → `http.Handler` (`tunnel.NewHTTPForwarder` or a `tunnel.StartStdio` process's `Handler()`; `SetTargets` replaces them while running). `Run` reconnects with backoff and ends with `tunnel.ErrRevoked` (403 at connect or close code 4003) or `tunnel.ErrReplaced` (4001).

## Tests

- `go test -race ./internal/machines/`: JWK parsing (RFC 8037 thumbprint vector; private or non-Ed25519 keys refused), codes and secrets, assertion verification (other key, `alg` none and HS256 confusion, tampering, wrong `typ`/`aud`/`sub`, expiry, lifetime, skew, jti), the device flow (pending, slow_down, denied, expired, one-time redemption, approval by another user owns the machine), rate limits, tokens (expiry, replay, revoked machine, inactive owner), the machine API (idempotent PUT, names it does not own, caps, refresh offline and online, logout), enrollment codes, replacement on re-enrollment, the machines cap, and the pages (`/activate`, `/machines`, `/admin/machines`, CSRF, the portal shell).
- `go test -race ./internal/federation/tunnel/` (`machine_test.go`): one connection carries every tunnel of a machine, new tunnels without reconnecting, the sync tick, `DropMachine` → `ErrRevoked`, a newer connection replaces the older (also across replicas), revoking one tunnel keeps the others, unknown targets get 502, machines are independent, the relay reaches every tunnel of a machine held elsewhere.
- `make test-integration`: `internal/store/machines_integration_test.go` (RLS, unique live names, device requests, enrollment code single use under 10 concurrent consumers, tokens, jti replay, machine tunnels and the owner FK, transfer, revocation, inactive owners) and `TestIntegrationMachineConnectionRelayAcrossReplicas` (`cmd/gateway`: two in-process gateways; a machine enrolls and registers two servers on A, connects once to A, refreshes both through B, both servers' tools are called through B's `/mcp`, the machine token opens no MCP session, revocation on A ends the connection with `ErrRevoked` and both servers stop).
- `make test-security` (`test/security/fed_machines_test.go`): assertion forgeries, revoked machines and inactive owners, token scope, cross-machine and cross-user servers and tunnels, device and user code guessing, the approval page (sign-in, CSRF, pending users, binding to the approver, 4x4 fingerprint), enrollment code single use under concurrency, revocation (owner and admin) closing the live connection.
